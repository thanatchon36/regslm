# Design decisions

Format: ID — date — decision — why. Newest at the bottom.

- **D-001** — 2026-10-15 — Repo lives at `~/github/regslm` (Linux FS), not `~/regslm` as the owner's brief said. Same constraint (never under `/mnt/c`), existing checkout.
- **D-002** — 2026-10-15 — Two virtualenvs: `.venv` (core + vLLM serving/teacher) and `.venv-train` (Unsloth/TRL/PEFT). vLLM and Unsloth pin different torch builds; declared as a uv extras conflict. Make targets call `uv run --no-sync` so one env never silently re-syncs the other.
- **D-003** — 2026-10-15 — Obligation unit of output is `Extraction{unit_id, obligations[], rationale?}` per corpus unit; a unit with no obligation is an explicit empty list (needed for hallucination metrics and the `no_hallucinated_obligation` reward).
- **D-004** — 2026-10-15 — `citation.span` = half-open character offsets of the trigger sentence in the unit text (not token offsets): tokenizer-independent, so comparable across Qwen/Gemma/Typhoon and across languages.
- **D-005** — 2026-10-15 — Thresholds normalised to `{value: float, unit: str, comparator}`; one threshold per obligation (the binding one). Multiple thresholds → multiple obligations. Keeps numeric exact-match and perturbation checks well-defined.
- **D-006** — 2026-10-15 — Text fields are copied from the source (near-verbatim), not paraphrased; this makes span grounding checkable and keeps the student from learning teacher paraphrase style.
- **D-007** — 2026-10-15 — Teacher run with `kv_cache_dtype=fp8`, `max_model_len=4096`, eager mode: the Windows compositor holds ~1.3–1.5 GB VRAM, leaving ~10.8 GB; 14B-AWQ weights take ~9.4 GB, so KV room is the bottleneck (see results/runs/teacher-smoke).
- **D-008** — 2026-10-15 — Qwen3 thinking mode disabled for the teacher (`enable_thinking=False`); the "label + rationale" variant asks for an explicit short `rationale` field instead, so rationale length is bounded and token budgets are comparable (RQ2).
- **D-009** — 2026-10-15 — Numeric perturbation (`schema/perturb.py`): quantities scaled by a factor in [0.55,0.85]∪[1.2,1.8] keeping decimals; dates shifted ±3–11 days and ±1 year; references/section numbers untouched; seeded per text. Memorisation = model emits an original value on perturbed text.
- **D-010** — 2026-10-15 — Licence tiers P/L/X (docs/sources/LICENSES.md). Unclear terms are treated as restrictive.
- **D-011** — 2026-10-15 — Train only on tier-P text, so a single released model family suffices (MISSION allowed two variants; one permissive variant is simpler and avoids an unreleasable twin). L sources = out-of-distribution evaluation only.
- **D-012** — 2026-10-15 — Held-out rulebook: FCA SYSC (OGL v3.0), conditional on a sanctioned access route; fallback HKMA SPM.
- **D-013** — 2026-10-15 — robots.txt is binding even when an API is documented: eCFR `/api/versioner/v1/full/` is disallowed, so eCFR text comes from GovInfo bulk XML.
- **D-014** — 2026-10-15 — VRAM cap measured as total `nvidia-smi memory.used` minus the pre-launch idle baseline (Windows compositor ~1.3–1.5 GB is not part of the run). Both raw and baseline-subtracted peaks are logged. With 12,282 MiB total and the compositor resident, no run can physically exceed ~10.7 GB anyway.
- **D-015** — 2026-10-15 — Teacher config that fits (results/runs/teacher-smoke): Qwen3-14B-AWQ, `gpu_memory_utilization=0.87`, `max_num_batched_tokens=1024`, `max_num_seqs=8`, `kv_cache_dtype=fp8`, `attention_backend=TRITON_ATTN` (FlashInfer JIT needs nvcc, absent). Weights 9.44 GiB, KV 0.43 GiB ≈ 5.6k tokens. 8/8 schema-valid; 85 tok/s in eager mode on a toy batch — too slow for 30–50k units in 12 GPU-h, so the labelling budget plan is: (1) throughput benchmark on 200 real units with CUDA graphs + prefix caching + `max_model_len=3072`; (2) if projected > 12 h, label-only on the largest N that fits and the rationale variant on a 10k subset (RQ2 is compared at equal token budget, so it does not need 50k rationales), recorded as a scope cut.
- **D-016** — 2026-10-15 — `Extraction.rationale` precedes `obligations` so that under guided JSON decoding the rationale is produced first (a short chain of thought), as in Distilling step-by-step. Label-only variant sets it to null. Students trained on the rationale variant emit it too; at inference it is parsed and dropped.
- **D-017** — 2026-10-15 — **Incident, disclosed:** before D-013, the eCFR adapter fetched a small number of files from `www.ecfr.gov/api/versioner/v1/full/`, which robots.txt disallows. Cause: `urllib.robotparser` ends a group at a blank line, so the indented Disallow after a blank line was ignored. The cached responses were deleted and nothing derived from them is in the corpus. Fix: `corpus.base.robots_lines` (blank lines and indentation ignored, as Googlebot does) + regression test `tests/test_corpus_base.py`.
- **D-018** — 2026-10-15 — `PoliteClient.get(headers=...)` added for content negotiation (EUR-Lex Cellar); headers are part of the cache key. Whole-title sources (eCFR bulk XML) expose `parse_all(raw, selection)`; `parse(raw)` stays the single-document contract.
- **D-019** — 2026-10-15 — Number formats: EU decimal comma ("4,5 %") and space-grouped thousands ("EUR 5 000 000") are parsed in perturbation and in reward/eval numeric normalisation; perturbed values keep the source's format.
- **D-020** — 2026-10-15 — **Models generate quotes, not offsets.** Teacher pilot (200 CRR/CRD units): only 192/393 model-written spans covered the trigger, 101 were out of bounds, and all 6 invalid outputs were `span {0,0}`. Generation schema `GenExtraction` has `citation.quote`; `schema.generation.resolve` maps quotes to character spans (exact → normalised → fuzzy alignment ≥ 0.85 coverage, window ≤ 1.3× quote). The stored/evaluated `Extraction` keeps character spans (MISSION schema unchanged). Unresolved quotes = ungrounded obligations: dropped from labels and counted; in evaluation counted as false positives; in rewards they lower `citation_resolves`. Prompt version v2.
- **D-021** — 2026-10-15 — Teacher throughput: eager mode (CUDA graphs OOM even with 4 capture sizes at 0.89), `max_num_seqs=24` exploits prefix caching of the ~900-token system prompt: 3,848 units/h (vs 2,416 at 8 seqs). Projection: 30k units ≈ 7.8 GPU-h.
- **D-022** — 2026-10-15 — Gold sample: 300 units; 20 % Thai (if available); per-document allocation ∝ sqrt(#units); 15 % of each document's draw from units with no deontic trigger in text + heading, so the silver trigger pre-filter's miss rate is measured on gold. Thai trigger list includes "ให้", which is very common, so the Thai filter is nearly a no-op by design (conservative).
- **D-023** — 2026-10-15 — Held-out rulebook: **AMLD4** (EUR-Lex, tier P, AML domain unlike the prudential/conduct training mix) until FCA SYSC is obtainable (owner action); when SYSC arrives it is added as a second held-out set. HKMA SPM stays a tier-L OOD eval set. Deviation from MISSION §1.5 default because both named defaults are currently blocked (FCA terms) or non-permissive (HKMA).
- **D-024** — 2026-10-15 — Splits are grouped by **article/section** (first two path levels), not by unit: sibling paragraphs share wording, so a unit-level split leaks. Stricter than MISSION ("by unit"); reported as such.
- **D-025** — 2026-10-15 — Post-cutoff slice: base models' cutoffs are not all documented; use the latest public release date among the ladder's bases (Qwen3: 2025-04-29; Gemma 3: 2025-03-12; Typhoon 2 / SEA-LION v3 earlier) as a conservative upper bound: units with `last_amended` ≥ 2025-05-01. N reported.
- **D-026** — 2026-10-15 — Pilot v2: 100 % valid JSON, 8.3 % unresolved quotes — all cases were list points where the model quoted the lead-in (HEADING). Fix: `resolve` maps a quote found in the heading to the whole point (guide R7), and prompt v3 asks for quotes from TEXT.
- **D-027** — 2026-10-15 — Teacher budget (12 GPU-h) at ~3,870 units/h (prompt v3): (1) eval sets test+dev+silver_val+heldout, all units, label variant (8,457 units ≈ 2.2 h) — no filter, so the trigger filter's miss rate is measured on them; (2) train units with a deontic trigger in text+heading, label variant (19,918 ≈ 5.1 h); (3) train units without a trigger (9,218) get rule-based empty labels (`origin=rule_empty`), never teacher calls; (4) rationale variant on a 10k subset of (2) (≈ 3 h); (5) gold passes + Thai with the remainder. Consequence for the pre-registration: the corpus has < 50k train units, so the label-budget grid is N ∈ {500, 2k, 10k, 20k} (20k ≈ all teacher-labelled train units); N counts teacher-labelled units, rule-empty units are added at the corpus ratio.
- **D-028** — 2026-10-15 — Thai added (corpus `2026.10.15-4ce7830f`: 44,045 units, 40 docs). BoT notification PDFs lose sara am's nikhahit ("ก าหนด"); repaired by rule (space + sara aa never valid Thai): 4,941 occurrences fixed. Gold sample drawn (300: 240 en / 60 th, 40 untriggered; excludes held-out AMLD4 and the FIBA English translation). **Splits frozen** at this corpus version (`data/splits/`); re-splitting moved 1,758 English units, mostly silver_val↔train (silver_val is resampled from train), before any training. Teacher labels are content-addressed, so already-labelled units stay valid wherever they moved.
- **D-029** — 2026-10-15 — Training defaults pre-registered in docs/specs/train.md: LoRA r16/α32 all linear, lr 2e-4 (full 2e-5), effective batch 16, 2 epochs but ≥ 300 steps, completion-only loss, seq ≤ 2,048 (longer dropped and counted). Students get a short system prompt, not the teacher's rules (what is learned comes from data). Nested label subsets (500 ⊂ 2k ⊂ 10k ⊂ 20k). Rule-empty units added at the train ratio. Evaluation without guided decoding (validity is measured); guided decoding is an RQ4 serving variant.
- **D-030** — 2026-10-15 — GPU jobs are chained by `scripts/run_queue.sh <queue file>` running in tmux session `queue` (waits for GPU < 2.5 GB, then for each run's `exit.json`; skips DONE runs; log `results/queue.log`). Phase-1 queue: `config/queue_phase1.txt`. Exact base revisions recorded in `results/base_revisions.json`.
- **D-031** — 2026-10-15 — **Owner decision:** PRA Rulebook and MAS Notices/Guidelines stay excluded entirely (option a): not fetched, not trained on, not evaluated. Listed under Threats to Validity as a jurisdiction-coverage limit.
- **D-032** — 2026-10-15 — Hugging Face namespace for releases: `thanatchon36` (owner). Model repos: `thanatchon36/regslm-qwen3-<size>-oblig[-awq|-gguf]`; dataset: `thanatchon36/regslm-corpus`. The README example `regslm/qwen3-1.7b-oblig-awq` from MISSION becomes `thanatchon36/regslm-qwen3-1.7b-oblig-awq`.
- **D-033** — 2026-10-15 — Base model availability (HF, 2026-10-15): SEA-LION v3 has no ≤ 4B model (smallest: `aisingapore/Llama-SEA-LION-v3-8B-IT`, Llama 3.1 licence), so RQ5's "Thai-pretrained at ≤ 4B" uses **Typhoon 2** (`scb10x/llama3.2-typhoon2-1b-instruct`, `-3b-instruct`, Llama 3.2 licence) and SEA-LION v3 enters as one 8B QLoRA comparison at N = 10k. Gemma 3 1B/4B are gated (manual licence acceptance by the owner's HF account) and carry the Gemma Terms of Use — derived weights would be released under Gemma terms, not Apache-2.0, and named accordingly. Qwen3-8B QLoRA uses Unsloth's pre-quantised `unsloth/Qwen3-8B-unsloth-bnb-4bit` (same weights, NF4; avoids a 16 GB download and host-RAM pressure at load).
- **D-034** — 2026-10-15 — Perturbed evaluation redesigned: only 440 of 4,407 test units contain a perturbable number. `test_perturbed` = the whole test set with numbers perturbed where present (OF1 comparable with `test`; units without numbers are identical, so their predictions are reused). Memorisation rate is computed on `mr_pool` = all 1,129 numeric units of test ∪ dev ∪ silver_val ∪ heldout, perturbed (gold added once adjudicated). dev/silver_val are used for checkpoint selection only in unperturbed form.
- **D-035** — 2026-10-15 — Grid shrunk before any result (first projection 319 GPU-h vs 100): per-run eval ≈ 7.5k units (test 4,407 + perturbed numeric 440 + mr_pool 689 extra + heldout 641 + silver_val 1k selection subset + gold 300); epochs = 1 for N ≥ 10k, 3 for N ≤ 2k (≥ 300 steps); pre-registered budget rule applied in order — 8B then 4B to 2 seeds, 8B N=20k single seed, GRPO cap 1.5 h/run, Thai cells 2 seeds; quantization on one checkpoint per size, 2,129-unit eval subset, CPU-only for 0.6B/1.7B; SEA-LION 8B moved to an optional block run only if measured budget allows. Projection (assumed throughputs): blocks 1–7 = 101.5 GPU-h; re-projected with measured throughput (`experiments/budget.py`, `results/throughput.json`) before each block; further cuts follow §7 order.
- **D-036** — 2026-10-15 — **Annotation guide v2.0 / teacher prompt v4** after an independent expert review (8 must-fix items): comparator rule (limit on a quantity → `must` + compliant region; prohibited act → `must_not` + prohibited region); no invented subjects (party-less `shall be` calculation rules → `[]`); modals inside noun phrases, deeming, scope, enabling/delegation clauses, commentary and fragments → `[]`; Thai rules for ให้ (directive vs "give"/deeming/repeal/composition), อาจ/สามารถ (permission vs possibility), subject in ในกรณีที่-clauses, delegation phrases kept verbatim; `value` = number as written (Thai digits/words converted, scale word in `unit`). Scoring/rewards parse Thai number words via PyThaiNLP token-level conversion. The v3 eval-labelling run was **stopped** after 2,984 units (0.65 GPU-h) because its labels follow the superseded rules; the cached v3 outputs are kept for a prompt-version sensitivity analysis (v3 vs v4 agreement on the overlap). Teacher budget still fits: ~1.3 GPU-h used of 12.
- **D-037** — 2026-10-15 — Pre-registration v2 after an independent methodology review: paired unit bootstrap + per-seed consistency (no seed-level CI with 2–3 seeds); SESOI 2 / 3 (Thai, fields) / 5 (num440, gold); non-inferiority crossover rule; no student-vs-teacher claim on silver; memorisation decomposition (original / perturbed / other / missing) on mr_pool with two perturbation seeds; silver_val uses enumerated; post-cutoff, held-out-gap and placebo decision rules; Holm families declared; budget rule never reads metrics and cut cells keep their rows.
- **D-038** — 2026-10-15 — Teacher v4 pilot over-suppressed: empty rate 15 % → 49 %; of 12 sampled v3-only units ~6 were correct removals (calculation/deeming/delegation) and ~6 were list points under a lead-in sentence wrongly emptied. Guide v2.1 / prompt v5 make R7 explicit (a point under a lead-in with trigger + named party is an obligation; content → object or condition). v4 eval labelling stopped after minutes.
- **D-039** — 2026-10-15 — **Owner decision:** skip Gemma 3. MISSION's second model family is dropped in favour of clean curves on the Qwen3 ladder (MISSION §7); the Llama-3.2-based Typhoon 2 (RQ5) is the only non-Qwen family. Reported as a threat to validity (single main family).
- **D-040** — 2026-10-15 — Teacher runner submits 512 units per `llm.chat` call (was 64): with small batches the slowest unit stalled the batch and throughput fell to ~2.2k units/h; at 512 it is ~6k units/h.
- **D-041** — 2026-10-15 — Second perturbation draw (`mr_pool_s1`) only in zero_shot, sft_ladder_10k and grpo blocks (where MR claims are made); every model gets the decomposition on `mr_pool_s0` (which reuses test_perturbed predictions). 14B zero-shot now also predicts `test` and `mr_pool_s0`. Projection: blocks 1–6 = 97.6 GPU-h, block 7 (Thai) = +5.3 → pre-registered cuts (drop block 8, Thai to 1 seed) will apply unless measured throughput is better than assumed.
- **D-042** — 2026-10-15 — A unit whose prompt exceeded `max_model_len` aborted the whole eval-labelling batch (vLLM rejects the request). Teacher `max_model_len` 3072 → 4096 (system prompt v5 ≈ 1.9k tokens, prefix-cached) and a per-unit length guard: prompts leaving < 512 output tokens are recorded as `too_long` (valid = 0) and not sent; others get `max_tokens` capped to the room left. Cache keys unchanged, so the 1,654 units labelled before the crash are reused.
- **D-043** — 2026-10-15 — Zero-shot baselines get the full teacher prompt v5 + JSON Schema in the prompt (no guided decoding), not the short student prompt: avoids a strawman baseline for the RQ1 crossover. Context 5,120 tokens for zero-shot runs.
- **D-044** — 2026-10-15 — Sets that cannot exist yet (gold before owner adjudication) are skipped by `predict` and listed as `pending_sets` in predict_meta/eval.json; they are predicted later with `regslm predict --sets gold` — this is the pre-registered "gold pending" status, not a change of eval sets.
- **D-045** — 2026-10-15 — `scripts/autopilot_phase1to2.sh` (tmux `autopilot`) chains: eval-sets after eval labels → gold build after gold passes → zero_shot, sft_ladder_10k, placebo blocks after the teacher queue (each emitted through the metric-blind budget gate). It stops before block 3 so the throughput re-projection is reviewed and committed first (prereg §7).
- **D-046** — 2026-10-15 — Gold pass B (Qwen3-8B-AWQ) looped on JSON whitespace until max_tokens on 132/300 units (44 % invalid). Fix: compact JSON grammar (`--compact-json` → engine-level `structured_outputs_config.disable_any_whitespace`; the per-request flag is silently ignored by xgrammar in vLLM 0.31 — a first re-run with it was byte-identical and its cache rows were deleted). Pass B validity 56 % → 94.7 %. The 14B teacher keeps the default grammar (0.6 % invalid) so silver labels stay consistent within one configuration. Inter-pass agreement remains low (span F1 0.545, has-any κ 0.17): pass B over-extracts (9 % empty vs 50 % for pass A) — reported as is.
- **D-047** — 2026-10-15 — Gold adjudication UX: a tolerant comparison (token-set F1 thresholds) decides which units need the owner; strict agreement metrics are still reported. Disagreements are tiered (1 = existence/modality, 2 = field boundaries) and exported as an Excel-friendly CSV with an import command.
- **D-048** — 2026-10-15 — **Owner decision:** the owner delegated gold adjudication to Claude ("ผมอนุญาตให้คุณทำ"). MISSION §1.3 says "adjudicated by me"; this is a deviation (prereg amendment A2). Claude (Opus 5.5, a non-Qwen family, so not the teacher or pass B) adjudicated all 268 disagreement rows in four parallel slices, each following docs/ANNOTATION_GUIDE.md v2.1, before any student or zero-shot model was evaluated on gold (blind to model outputs). Every decision has a one-line rationale in `data/gold/adjudication_rationale.csv`; the filled CSV is `data/gold/adjudicate_claude.csv`. Result: A 101, B 22, edit 145 (40 of them `none`); the 32 agreed units were reviewed and kept. `gold.jsonl`: 300 units, 169 empty, 160 obligations. Ambiguity classes are logged in docs/INTERPRETATIONS.md. Eval sets rebuilt: gold joins the memorisation pool as planned in D-034 (`mr_pool_s0/s1` 1,400 → 1,451 units, 287 → 299 targets); all other sets byte-identical. Paper: gold is reported as "LLM-adjudicated (Claude), owner-authorised", listed under Threats to Validity; an owner spot-check of a random sample is optional and, if done, its agreement is reported.
